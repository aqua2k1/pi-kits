# 架构

[index.ts](../index.ts) 记录最后一条助手消息的结束状态，在任务结束且保持空闲后调用[共享通知库](../../../shared/README.md)；配置由[共享配置服务](../../../shared/config/README.md)读取。

## 文件地图

| 文件 | 职责 |
|---|---|
| [index.ts](../index.ts) | 生命周期注册、状态记录、延迟调度和取消 |
| [index.test.ts](../index.test.ts) | 事件、状态、计时器及配置接线测试 |
| [package.json](../package.json) | 扩展入口、资源名、依赖和测试脚本 |

## 数据流

1. 扩展加载时读取配置；启用时注册事件处理器。
2. `message_end` 记录助手消息的结束状态。
3. `agent_settled`（任务收敛后的生命周期事件）取消旧计时器，检查 TUI 模式与空闲状态，再安排延迟回调。
4. 新输入、任务启动或会话切换取消待发通知；任务开始前和会话起止还会重置状态。
5. 回调再次检查模式与空闲状态，再调用共享通知入口；正文映射见[使用](usage.md)。

## 约束

- `index.ts` 从共享配置读取开关后再注册事件，避免禁用状态产生处理器和计时器副作用。
- 通知调用集中在延迟回调中，并在调用前复查模式和空闲状态，避免后加载扩展启动续跑时发送过早的完成通知。
- 结束状态只由助手消息更新，任务和会话边界重置状态，避免工具结果或上一任务的错误污染新通知。
- `index.ts` 捕获共享通知调用的同步异常与异步拒绝，使通知失败不打断任务流程。

## 测试

在仓库根目录执行：

```sh
npm test --workspace=pi-notify
```

[index.test.ts](../index.test.ts) 覆盖事件注册、空闲 TUI 筛选、正文映射、最终状态覆盖、取消与替换计时器、发送前复查、异常隔离、禁用及等待时间传递。
