# UI 协议与适配边界

## 状态与定位

项目目标单独记录在 [UI 项目目标](goals.md)。本文描述实现这些目标的设计与
实施策略，不表示以下协议、目录或前端已经实现。
当前 `shared/ui/` 主要提供共享终端 UI；现有能力见
[共享 UI 文档](../../docs/ui.md)。

## 采用语义协议，而非通用控件 DSL

协议描述“展示什么、允许哪些动作、返回什么结果”，不规定所有前端如何布局。
例如：

- 问卷：问题、选项、自定义答案、确认与取消。
- 只读文档：内容、格式与展示请求。
- 统计报告：结构化报告数据。
- 任务视图：任务快照、订阅与允许的操作。

不以终端行数、ANSI、DOM、标签页布局或窗口尺寸作为跨前端契约。
TUI、WebUI 与 GUI 可选择适合各自环境的呈现方式，不要求布局完全一致。

普通 `select/input/confirm` 优先复用 Pi 已有能力，避免重复建立万能 UI 框架。
只有多个前端实际出现重复需求时，才进一步提炼小型声明式组件协议。

## 职责边界

| 层 | 职责 |
| --- | --- |
| 扩展业务与状态 | 答案规则、统计计算、任务执行、业务数据与状态转换 |
| 共享 UI 协议 | 语义请求、结果、动作、请求关联与能力契约 |
| 共享 UI 适配 | 展示、输入、事件路由、前端选择与交互生命周期 |
| 具体前端 | 终端组件、浏览器 renderer 或 GUI 控件的实现 |

业务规则不能迁入共享 UI，仅为方便 renderer 而改写业务行为。
可复用的问卷 reducer、统计 report、任务 snapshot/subscribe 等应继续作为
独立数据与状态逻辑，由不同前端消费。

共享模块仍是库：不注册工具、命令或 Pi 生命周期处理器。
扩展入口负责注册与宿主生命周期连接，通过共享 UI 入口发起交互。

## 建议组织

以下是目标结构示意，不要求预先创建未使用的适配器：

```text
shared/ui/
  protocol.ts       # 语义请求、结果、动作、能力
  host.ts           # 统一入口与适配器选择
  lifecycle.ts      # 取消、完成与清理
  tui/              # Pi custom、终端组件与现有 primitives
  web/              # 传输、事件适配与客户端 renderer
  gui/              # 按需增加
  docs/             # 协议、边界与演进约定
```

扩展应调用问卷、文档或任务视图等语义入口，而不是自行按前端分支。
统一入口的具体 API 随实际迁移确定，不将上述文件名或结构视为已实现接口。
业务专属数据契约由对应业务模块拥有，共享协议不应反向依赖扩展注册入口。

## 生命周期与能力

- 统一请求关联、完成、用户取消、外部中止与一次性清理的语义。
- 按键、鼠标命中、DOM 焦点、IME 与布局由具体适配器管理。
- 创建交互请求不等于客户端已经挂载；需要挂载确认时，应明确约定事件。
- 对不支持的能力明确返回“不支持”，或采用已定义的降级，不静默失效。
- WebUI 需要客户端 renderer 与传输实现，服务端适配器不能自动生成浏览器 UI。
- Pi RPC 对 `custom` 等能力的限制应在适配边界处理，不能假设包装即可消除。

后端打开文件或发送桌面通知，不等于远程浏览器执行同样的操作。
保持本机操作的明确语义；前端展示或通知使用独立事件或受控资源地址，
不直接将服务器文件路径当作客户端 URL。

## 渐进实施

1. 先迁移问卷与只读预览，验证语义协议、取消与能力降级边界。
2. 保留现有 TUI 体验，将终端实现逐步归入共享 UI 适配层。
3. 再迁移 stats 与 subagent 的展示，复用报告、快照、订阅和业务操作。
4. 修补标准 RPC 路径的展示缺口，验证真实客户端行为。
5. 若明确要求无 Herdr 部署，独立拆分执行 backend 与可选终端视图能力。

不一次性统一所有控件，不为尚未存在的前端建设完整布局引擎。
验证应覆盖业务结果一致性、取消与中止、清理、重连、会话切换及能力不足时的行为；
仅有 TUI 测试或 RPC mock 不代表跨前端体验已经得到验证。
