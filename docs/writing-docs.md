# 文档写作规范

本仓库的文档同时给人和 Agent 读。每个扩展的文档放在自己目录里，按需分层，读者读到够用即停。

## 分层

| 层 | 文件 | 何时需要 | 读者的问题 |
|---|---|---|---|
| L0 | `AGENTS.md`、根 `README.md` | 始终 | 仓库里有什么，从哪进入 |
| L1 | `extensions/<name>/README.md` | 每个扩展 | 这是什么，怎么跑起来 |
| L2 | `docs/usage.md` | 有命令、工具或交互 | 怎么用 |
| L2 | `docs/configuration.md` | 有配置项 | 有哪些键，默认值是什么 |
| L2 | `docs/architecture.md` | 模块 ≥5 个，或有跨文件约束 | 改代码前要知道什么 |
| L3 | `docs/notes/YYYY-MM-DD-<topic>.md` | 调研、实验、决策 | 当时为什么这么选 |

没有内容可写的文件不创建。单文件扩展只需要 README。

共享能力（`shared/`）只在 shared 里写一次，扩展里链接过去。

## 写法

1. 只描述已实现的行为。
2. 现在时，肯定句，主语是功能本身：「`/commit` 根据暂存区 diff 生成提交信息」。
3. 示例优先于解释。每个命令、工具、配置先给一个可复制的例子。
4. 一个事实只写一处，其他地方链接。
5. 签名、类型、默认值以代码为准，文档给文件路径，不抄代码。
6. 需要提醒读者的坑，用一行写在相关内容旁边，只写读者真会遇到的。
7. 不写这些：非目标、不支持清单、免责声明、背景铺垫、对未来的承诺。
8. 禁用词：本文档旨在、需要注意的是、请务必、切勿、可能会、一般来说、建议谨慎。
9. 链接用相对路径。

## 长度上限

- README ≤ 60 行
- usage、configuration ≤ 150 行
- architecture ≤ 200 行

超出时拆分，或删掉读者用不到的部分。

## 模板

### README.md

```markdown
# <扩展名>

<一句话：它做什么。>

## 安装

<安装命令或配置片段。>

## 快速开始

<最小可运行示例，附一句预期结果。>

## 文档

- [使用](docs/usage.md)
- [配置](docs/configuration.md)
- [架构](docs/architecture.md)
```

只列实际存在的文档。

### docs/usage.md

~~~markdown
# 使用

## <命令或工具名>

<一句话说明。>

```
<示例>
```    

| 参数 | 说明 |
|---|---|
| ... | ... |
```

每个命令或工具一节，按用户使用频率排序。

### docs/configuration.md

```markdown
# 配置

配置位置：`<路径>`，配置键 `<key>`。

| 键 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| ... | ... | ... | ... |

## 示例

```json
...
```

只有表格和一个完整示例。字段的校验规则见 `<schema 文件路径>`。

### docs/architecture.md

```markdown
# 架构

<一段话：整体怎么工作。>

## 文件地图

| 文件 | 职责 |
|---|---|
| `index.ts` | ... |

## 数据流

<按步骤，3~7 步。>

## 约束

- <改代码时必须保持的事实，每条一行。>

## 测试

<怎么跑，测试文件对应哪些模块。>
~~~

「约束」是 Agent 改代码前最需要的一节：写跨文件的不变量，不写显而易见的事。


### docs/notes/YYYY-MM-DD-topic.md

```markdown
# <主题>

日期：YYYY-MM-DD
结论：<一句话。>

## 过程与数据

...
```

notes 记录当时的判断，允许与现状不同，不被其他文档引用为现行行为。

## 提交前检查

- [ ] 每个文件在上表中有对应层级
- [ ] 没有禁用词和免责声明
- [ ] 每个命令、配置项有示例
- [ ] 没有重复 shared 或其他扩展已写过的内容
- [ ] 行数在上限内
- [ ] 链接可打开
